# Accepted amendment to ADR 0002: Core v0.6 ingestion reconciliation

- **Status:** Accepted
- **Date:** 2026-08-04
- **Amends:** [ADR 0002](../0002-provenance-bound-report-snapshots-and-subscriptions.md)
- **Related decision:** [ADR 0003](../0003-consumer-side-producer-adapters.md)
- **Related architecture:** [Core v0.6 publication ingestion](../../architecture/core-v0.6-publication-ingestion.md)

## Purpose

ADR 0002 correctly requires provenance-bound report snapshots and separates
frozen snapshots from refreshable views. This amendment binds its source and
refresh language to Core v0.6 canonical publication and producer-manifest
identity.

It does not change the decision that issued snapshots remain historically
explainable after source, policy, override, report-definition, or presentation
changes.

## Reconciliation

### Exact imported-source identity

A structured report snapshot that includes producer evidence must be capable of
identifying, as applicable:

- canonical Publication Record ID;
- complete work identity;
- publication kind;
- record-set ID and revision;
- exact manifest contract, path, digest algorithm, and digest;
- exact referenced Academic Work Registration revision;
- producer contract version;
- optional source-record reference and contract;
- predecessor publication ID;
- withdrawal and series state observed for the generation;
- producer reader/contract identity; and
- Meridian adapter/projection-contract identity.

A catalog row, producer package version, work ID, or convenience `latest` path is
not an adequate frozen source reference.

### Refreshable views repeat verification

Refreshing a view must not reuse an old catalog row as authority. It must repeat,
for current authorized state:

1. candidate discovery;
2. canonical Publication Record reload;
3. exact registration reload where applicable;
4. withdrawal and series-state reload;
5. producer compatibility and adapter selection;
6. authorization;
7. exact manifest verification; and
8. producer-contract parsing and projection.

The resulting refresh is a new identifiable generation observation. It does not
rewrite a previously issued snapshot.

### Supersession and withdrawal

A superseded or withdrawn publication may remain the exact historical source of
an issued snapshot. Current generation applies current selection and withdrawal
policy, while historical snapshots preserve the original source and observed
state.

Withdrawal does not permit silent deletion or substitution of a different source
inside an issued snapshot. Separate retention or lawful deletion policy may act
on the snapshot, but it must not falsify provenance.

### Cached projections

A cached producer projection is derived state and must bind to exact publication,
manifest, producer contract, and adapter/projection identity. Supersession,
withdrawal, contract changes, adapter changes, or authorization changes may make
it stale for current use without mutating the historical projection.

## Consequence

ADR 0002 remains accepted. This amendment and ADR 0003 govern how Core v0.6
producer publications are verified and represented in report provenance.

## Implementation status

The exact cached-projection requirement is implemented by
[`exact-projection-snapshots-and-cache.md`](../../architecture/exact-projection-snapshots-and-cache.md).
Projection snapshots bind exact source, adapter, reader, scope, purpose, and
authorization-policy identity. Fresh assessment may classify them as stale,
historical, or unverifiable without mutating their original bytes. Report
snapshots remain separate future work.
