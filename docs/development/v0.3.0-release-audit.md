## Calculation-state and silent-zero audit — CONFORMS

The first substantive audit pass challenged the Grade calculation layers at
the boundary where missing or unresolved academic state could accidentally
become numeric zero.

Inspected runtime families:

```text
meridian/grade_policy.py
meridian/conventional_grade.py
meridian/standards_grade.py
meridian/standards_grade_profile.py
meridian/hybrid_grade.py
```

The policy vocabulary is closed. Numeric `zero` is an explicit state
consequence only for `missing` and `incomplete`; it is rejected for pending,
excused, excluded, not-applicable, insufficient-evidence, unavailable,
withdrawn, invalid, and unresolved states.

Zero is therefore a policy consequence, not a fallback for unknown/non-Grade
state.

Direct Issue #61 adversarial coverage now walks the complete eleven-state
non-Grade vocabulary through both conventional and standards Grade
calculators under explicit exclusion. Every state preserves its source-state
identity, carries no fabricated earned/possible/conversion value, and yields
a nonnumeric insufficient final outcome when no real calculable evidence
remains.

The two zero-capable states are separately exercised under explicit `zero`
policy. Conventional Grade calculation creates a visible policy-owned zero
with the configured denominator and retained source state. Standards Grade
calculation may create a zero calculation contribution, but that contribution
does not increment `actual_calculated_result_count` and therefore cannot
satisfy minimum real-result evidence by itself.

Profile-constrained calculation was challenged with one real Meeting result
and one missing result under explicit zero treatment. The numeric zero did
not fabricate a proficiency level: the higher count predicate remained
indeterminate, its unknown standard remained unknown, and the matched
fallback band was not silently selected past that uncertainty.

Hybrid calculation was challenged with the same underlying missing state in
two policies. Under explicit zero treatment, the conventional component is a
genuinely calculated zero and retains its configured hybrid weight. Under
explicit exclusion, the conventional component remains nonnumeric
`insufficient`, is excluded, and the remaining active component is
renormalized. The hybrid layer does not turn an insufficient component into
zero on its own.

## Repository-only audit boundary

This audit is deliberately repository-only and must not be included in the
source distribution.

The final audit eventually records source lineage and final artifact hashes.
Embedding those hashes in an sdist that itself contained this file would create
a self-referential artifact. The existing v0.2.0 release process established
the same boundary.

Therefore:

```text
docs/development/v0.3.0-release-audit.md
    = repository-only release record
    != source-distribution payload
```

`MANIFEST.in` excludes this file, while `scripts/check_documentation.py`
continues to require it in the repository and `scripts/check_sdist.py` fails
closed if it appears in a built sdist.
