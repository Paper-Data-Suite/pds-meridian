# Meridian v0.4.2 release notes — candidate, not yet published

**Issue:** [#117](https://github.com/Paper-Data-Suite/pds-meridian/issues/117)
**Baseline:** Meridian v0.4.1
**Status:** Release-candidate preparation; full source, installed-wheel,
workstation, CI, and publication checks remain pending.

## Security correction

A student-restricted grant cannot authorize an unrestricted all-student
publication request. Teachers must explicitly establish legitimate protected
evidence access. Missing, denied, withdrawn, mismatched, or unavailable access
is represented truthfully, with bounded recovery guidance; no permissive
production policy is introduced.

## Teacher evidence journeys

Meridian discovers supported Core publications from ScoreForm, Quillan, and
Concord, validates installed reader contracts and precise protected scopes,
and presents native evidence through the teacher workflow. Shared Concord
evidence stays distinct from individual-student evidence. Missing or
unassessed does not become a fabricated proficiency or numerical score.

## Report 9 and instructional response

Teachers can analyze current Grade Item evidence without creating a
ReportingSnapshot. Native ScoreForm question observations and applicable
Quillan/Concord standards evidence inform a bounded report. Configured
proficiency levels are reused without silently adding categories; optional
planning groups are not authoritative proficiency assignments. Teachers can
save interpretation, interventions, and reassessment in append-only revisions,
reopen notes, and create a four-section local Markdown report. No SIS or LMS
write is implied and no intervention effect is claimed causally.

## Upstream qualification target

| Distribution | Exact qualification input |
| --- | --- |
| Core | 0.6.6 |
| ScoreForm | 0.13.0 |
| Quillan | 0.10.6 |
| Concord | 0.3.2 |

Core v0.6.6 provides the compatible deep-path Windows viewer handoff using a
per-user junction alias while preserving canonical source data. An accepted
shell launch is not confirmation that an external viewer displayed a file;
consumer authorization and integrity checks remain mandatory.

The unconditional runtime requirement remains `pds-core>=0.6.5,<0.7`;
qualification of this release candidate requires the exact published
Core 0.6.6 wheel. Producer dependencies remain optional.

## Release validation and boundaries

The same six installed dependency-isolation matrices remain in use:
`core`, `scoreform`, `quillan`, `concord`, `scoreform-quillan`, and
`all-adapters`. The new producer-specific Report 9 teacher journeys execute
inside their existing matrices, not in duplicate environments.

A clean, committed source candidate must pass the single authoritative
repository validator, artifact inventories, wheel and sdist checks, Twine,
installed package origin/isolation, `pip check`, and CI. Physical Windows 11
ARM64 + Python 3.13 x64 + OneDrive teacher acceptance must be recorded
separately. The v0.4.2 release audit will record qualified source/tree,
merged source, exact wheel hashes, matrix results, CI, and physical status.
Historical v0.4.1 release artifacts are not rewritten.
