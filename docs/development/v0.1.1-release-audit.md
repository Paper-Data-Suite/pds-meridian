## Findings and resolutions

### F-01 — release qualification did not prove the complete distribution boundary

**Classification:** release blocker

The baseline validator authenticated the four frozen upstream wheels and exercised
individual installed-wheel paths, but it did not yet prove all issue #14 release
properties:

- none of the frozen upstream distributions depends on `pds-meridian`;
- the source distribution has an explicit safe content/metadata boundary;
- installed-wheel tests are insulated from `PYTHONPATH`, `PYTHONHOME`,
  `PYTHONSTARTUP`, and user-site contamination; and
- ScoreForm, Quillan, and Concord coexist with Meridian in one fresh installed
  environment.

**Resolution:** commit
`156d7daeb4523305c8f5d002f3dba8b84a38a02b`
(`Harden v0.1.1 release qualification`).

The authoritative validator now performs the upstream dependency-direction
audit, validates exactly one wheel and one sdist, isolates installed-wheel smoke
environments from source-tree hooks, proves per-producer installed behavior, and
proves all-adapter coexistence in one fresh environment.

### F-02 — replay nondeterminism used Python equality rather than persistence bytes

**Classification:** release blocker

The projection cache compared a previously stored inventory and a repeated
projection with Python object equality. That could collapse differences that are
significant to Meridian's canonical persistence contract, including `0.0`
versus `-0.0` and different timezone-offset representations of the same instant.

Under one exact cache identity, differing canonical serialized projection output
must fail as nondeterminism.

**Resolution:** commit
`15a91bb007e8d60d980933349b03e0222e6df504`
(`Enforce canonical projection replay determinism`).

Replay nondeterminism now compares canonical serialized `EvidenceInventory`
bytes. Direct regressions prove signed-zero and timezone-representation
differences cannot silently reuse an existing snapshot.

### F-03 — cache scope was checked after protected snapshot bytes could be opened

**Classification:** release blocker

A fresh `read_projection_cache` authorization decision was obtained before cache
access, but the caller's requested purpose/student scope was compared with the
snapshot's persisted scope only after the snapshot bytes had been read. A caller
authorized for one scope who knew another scope's cache key could therefore
cause protected bytes to be opened before the mismatch failed.

**Resolution:** commit
`00945918ec8da1f875c42028bd378ec781367619`
(`Bind projection cache reads to authorized scope`).

Each cache-key directory now carries a zero-byte privacy-safe
`.scope-<authorization_scope_digest>` marker. The digest binds the exact purpose
ID and ordered requested student IDs without exposing those values in the
filename. After fresh cache-read authorization, the caller's exact scope digest
must match before the snapshot file is opened.

Cross-producer regressions prove both student-scope and purpose mismatches fail
before `_read_bounded()` opens any ScoreForm, Quillan, or Concord snapshot bytes.

### F-04 — release-facing metadata claimed unimplemented grading/reporting behavior

**Classification:** release blocker

The package Summary and CLI framing described Meridian as providing
policy-driven grading, evidence aggregation, and reporting even though v0.1.1
does not implement eligibility/selection policy, proficiency, Grade calculation,
or reporting policy. That violated the no-grading release boundary and the rule
to release only what the milestone has proven.

**Resolution:** commit
`b3715a2be0d3ddbefe5c0fb489417f407fbf4dc9`
(`Align release surface with implemented foundation`).

The distribution Summary now states:

```text
Publication ingestion and typed evidence diagnostics for Paper Data Suite
```

The CLI identifies the current ingestion/typed-evidence diagnostics foundation
and explicitly states that grading, proficiency, and reporting policy stages are
not implemented. Wheel and sdist validators enforce the Summary. The same commit
also corrected stale README wording that mentioned only ScoreForm and Quillan
after Concord support had shipped.

### F-05 — stale two-producer README wording

**Classification:** non-blocking documentation/release correction

One active README sentence still described optional ScoreForm and Quillan
adapter composition without Concord. It did not change runtime behavior but was
stale release-facing documentation.

**Resolution:** corrected in
`b3715a2be0d3ddbefe5c0fb489417f407fbf4dc9`.

### F-06 — grading/proficiency/reporting implementation remains future work

**Classification:** future v0.2 concern

The audit found no accidental Grade, proficiency, reassessment, attempt-selection,
scale-normalization, weighting, averaging, Academic Period assignment, or report
policy in the v0.1.1 runtime. Those responsibilities remain intentionally
deferred to later Meridian milestones.

### F-07 — new producers, generic parsing, Core redesign, and related expansion

**Classification:** deliberately out of scope

Portia/Vitrine adapters, generic parser/plugin discovery, batch ingestion, a new
Core contract/version, producer changes, and unrelated refactoring were not
introduced by this audit.

## Audit conclusions by release property

### Canonical Core authority — passed

Catalog rows remain bounded discovery observations rather than canonical
authority. The production path reloads exact Core Publication Record,
registration, series, and withdrawal state, evaluates producer compatibility,
selects the exact adapter, checks reader compatibility, authorizes access,
verifies the canonical manifest path/digest, passes the exact verified bytes to
the producer reader, and performs the established canonical race recheck.

No second Meridian-owned source of truth for Core lifecycle semantics was found.

### Exact adapter selection and dependency direction — passed

v0.1.1 supports exactly:

- ScoreForm `0.10.0`;
- Quillan `0.9.0`; and
- Concord `0.2.0`.

Selection remains explicit and fail-closed across producer, publication kind,
Academic Work contract, manifest contract, source-record expectations,
capabilities, and exact installed reader version. No nearest-version, generic
parser, producer-only, publication-kind-only, or plugin auto-discovery fallback
was found.

The frozen Core and producer wheel metadata is now automatically checked to
prove that none depends on `pds-meridian`.

### Producer-semantic isolation — passed

The audit confirmed the established distinctions remain intact:

```text
ScoreForm question alignment
!= Quillan standard observation
!= Quillan overall standard rating
!= Concord standard-backed Score

ScoreForm attempt != Concord Score revision/history
Concord Group Score != individual student Score
points != native Scale rating
native Scale A value 2 != native Scale B value 2
native numeric zero != producer-native non-score state
```

Blank, ambiguous, unrated, returned-without-full-review, and other producer-native
states are not flattened into zero or one universal missing/score state.

### Deterministic projection, serialization, and immutable cache — passed after F-02

Evidence serialization remains canonical and exact. Cache identity binds
canonical source observation, exact adapter/reader execution identity, purpose,
student scope, and authorization-policy identity. Replay now compares canonical
inventory bytes, and immutable historical snapshots are not overwritten or
selected by recency.

### Provenance completeness — passed

`EvidenceProvenance` retains the exact Core Publication Record, exact referenced
Academic Work Registration for academic evidence, matching withdrawal when
present, exact projection identity, and ordered producer-native provenance.

The released adapters preserve their own semantics rather than forcing a common
producer model:

- ScoreForm retains attempt/question hierarchy, source snapshots, scan/manual
  review references, retained-source digest/path where applicable, and producer
  timestamps;
- Quillan retains submission, review-unit, observation, standard, source-artifact,
  and producer timestamp provenance; and
- Concord retains Score identity/history, target and Scoring Scale identity,
  scorer/generator actors, status history, Evidence Link, Moderation, subject,
  locator, and source-publication provenance.

Concord Group/non-student evidence remains non-individualized.

### Authorization and privacy — passed after F-03

Publication ingestion authorizes before protected manifest access. Projection
cache reads obtain fresh authorization before protected cache access and now bind
the caller's exact purpose/student scope before snapshot bytes are opened.

Diagnostics remain read-only and fail closed without a deployment-provided
authorization provider. Student display data is not added to evidence subjects,
cache marker filenames do not expose purpose/student identifiers, and the audit
used synthetic test data only.

### Source lifecycle versus evidence preference — passed

Publication supersession and withdrawal are retained/evaluated as Core lifecycle
state. They are not converted into latest/highest/best/current attempt or score
preference. Historical snapshots remain immutable. Academic Period definitions
are not used to assign evidence to grading periods during ingestion.

### No-grading boundary — passed after F-04

The v0.1.1 runtime does not implement:

- evidence eligibility policy beyond explicit `unevaluated` ingestion state;
- attempt/reassessment selection;
- standards aggregation or proficiency calculation;
- percentage conversion or scale normalization;
- weighting or averaging;
- Grade or Grade Item calculation;
- Academic Period assignment;
- report snapshots, report generation, subscriptions, or delivery.

`EvidenceInventory` exposes exact filters only; filtering does not aggregate,
rank, normalize, or select evidence.

### Package and installed-artifact behavior — passed

The release qualification now proves:

- Python `>=3.11`;
- only `pds-core>=0.6,<0.7` is unconditional at runtime;
- exact optional producer dependency pins;
- no producer-to-Meridian dependency;
- deliberate wheel contents;
- deliberate source-distribution contents;
- installed package imports come from the fresh environment rather than the
  source tree;
- base and each producer adapter install independently;
- all three producer adapters coexist in one fresh environment; and
- Twine accepts both built distributions.
